# 饮食 Agent 量化评测结果

评测日期：2026-10-03（Asia/Shanghai）。以下为本机实际执行结果，不是目标值。

## 真实模型与 MySQL 评测

使用项目配置的 `qwen-turbo` 与 `qwen-max`，真实执行意图服务以及 HTTP→编排→MySQL→Agent→响应→Trace 落库链路。

数据为 **AI 辅助构造与标注**：600 条意图样本（120 个语义种子，每组 5 个相关表达），100 组多轮任务，共260个任务轮次。未经过独立人工复核，不能称为600条独立真实用户语料。餐食库使用仓库 SQL 快照，只有4道公共餐食。

| 指标 | 分子 / 分母 | 实测结果 |
|---|---:|---:|
| 规则修正后意图路由准确率 | 562 / 600 | **93.67%** |
| 端到端任务成功率 | 56 / 100 | **56.00%** |
| 多轮槽位补全成功率 | 60 / 60组需要补槽的会话 | **100.00%** |
| 最终非空推荐卡片白名单合规率 | 86 / 86个非空响应 | **100.00%** |
| 预定义关键节点 Trace 覆盖率 | 3304 / 3304个节点实例 | **100.00%** |
| “换一批”餐食重复率 | 0 / 0条调整后实际展示餐食 | **无法计算，不能写0%** |
| 换新成功率 | 0 / 30个调整轮 | **0.00%** |
| 要求推荐时的非空响应率 | 86 / 130轮 | **66.15%** |

任务分组：

| 类别 | 任务成功 | 解释 |
|---|---:|---|
| 澄清补槽 | 46 / 60 | 最终槽位60组全部正确，但14组没有返回所需餐食 |
| 上下文调整 | 0 / 30 | 初次推荐后匹配候选耗尽，全部换新轮次返回空结果 |
| 多餐规划 | 10 / 10 | 三餐覆盖与收尾响应符合用例要求 |

这说明当前的主要瓶颈包括餐食数据覆盖不足。正确理解槽位不等于完成推荐任务；空结果也不能证明去重体验良好。

意图分类明细：澄清96/100，健康风险100/100，调整100/100，多餐规划91/100，普通推荐90/100，其他85/100。这里的健康风险得分仅验证路由标签，不验证医学安全性或建议有效性。

服务识别结果在进入 `IntentReviseService` 之前为587/600（97.83%，包含服务内解析和兜底），修正后为562/600（93.67%），净下降4.17个百分点。否定或引用关键词存在误伤，例如“不需要你诊断或开处方”“不是要规划三餐”仍会触发关键词规则。未为了提高分数改写规则、Prompt或删除这些错例。

调用观测：共1068次真实Agent调用，1068次都有usage记录；累计报告1,452,124个Token。Agent调用平均耗时1146.18ms，P95为3840ms。这不是HTTP端到端P95，也不是费用金额。

## 故障注入

使用真实HTTP、Java服务、MySQL和Trace，只在外部 `ReActAgent` 响应边界注入受控故障。

| 故障 | 可用响应 / 注入次数 | 可用率 |
|---|---:|---:|
| 底层已抛出超时异常 | 40 / 40 | 100% |
| 空回复文本 | 40 / 40 | 100% |
| 非法JSON（3个要求JSON的Agent） | 30 / 30 | 100% |
| 空响应对象（自然语言澄清Agent） | 10 / 10 | 100% |
| 合计 | **120 / 120** | **100%** |

每个故障配置重复10次。验收要求目标Agent确实被调用、5秒内返回正确的响应结构与非空兜底文本；推荐/规划场景还要求实际有卡片。澄清Agent不要求JSON，所以没有将其算入非法JSON解析场景。

这个100%仅证明**异常已经抛出后的兜底可用性**。当前业务 `.block()` 没有显式时限，本实验没有证明无限挂起的网络请求能够自动按期取消。

## 候选充足时的 Java 去重规则验证

30组受控历史与候选集合，每组连续换3批，共90个换批轮次，实际返回270条推荐：

- 重复推荐：**0 / 270，重复率0%**。
- 非空批次：90 / 90。
- 每轮同时检查重排排除与会话历史累计。

这部分只执行真实Java重排与状态方法，没有LLM、HTTP和MySQL；不能用它替代上面的真实模型换批结果。

另有12个白名单边界用例覆盖编造ID、负数、空ID、字符串ID、重复ID、候选Top3之外ID、空数组、空回复和非法JSON，全部通过。最终卡片来源受代码约束，自然语言 `speechText` 的餐食事实仍需另行评测。

## 工程改动与验证

- 新增可重复生成的标注集、真实模型/HTTP/MySQL执行器、故障注入、独立评分与报告脚本。
- 修复 `AgentTraceService` 对Lombok fluent DTO的序列化：使用独立复制的Jackson映射器按字段记录，避免候选对象落成不可解析字符串。
- 该序列化回归测试在原实现下失败，修复后通过；没有更改路由规则、模型Prompt、排序逻辑或原HTTP序列化配置。
- `mvn test`：18个Java测试通过，外部评测入口在普通单测运行中按设计跳过。
- Python：11个评分与重评分测试通过。
- 独立代码审查已复核缺失分母、Trace证据、标注版本与重评分一致性。

标注1.1补充了调整轮继承清淡目标以及“快一点”的快速槽位验收。原1.0运行保留；对相同模型响应统一重新评分，700条记录与260轮原始响应均未修改，主要指标数值保持不变。
